# โฟลเดอร์ ml/ — โมเดลที่ใช้ในแอป

> **ข้อมูลที่ใช้เทรนทั้งหมดเป็นข้อมูลจำลอง (synthetic)** สร้างโดย `00_generate_synthetic_data.py`
> เพื่อสาธิตการทำงานของระบบ ไม่ใช่ข้อมูลการขายจริงของร้านใด ตัวเลขความแม่นยำที่แสดงในแอป
> จึงบอกได้แค่ว่าไปป์ไลน์ทำงานถูกต้อง ไม่ได้รับรองผลกับร้านจริง

## ลำดับการรัน (จากโฟลเดอร์ `ml/`)

```bash
pip install -r requirements.txt
python 00_generate_synthetic_data.py   # สร้าง synthetic_bakery_sales.csv
python 01_waste_reduction_model.py     # โมเดลความเสี่ยงของเสีย (RandomForestClassifier)
python 02_basket_analysis_model.py     # กฎซื้อคู่กัน (Apriori)
python 04_baking_demand_model.py       # พยากรณ์ปริมาณขายรายชั่วโมง (RandomForestRegressor)
python 05_export_for_app.py            # เขียน ../src/data/modelOutputs.json ให้แอปอ่าน
```

ผลลัพธ์ทำซ้ำได้ (seed คงที่) ไฟล์ `.pkl` ที่เทรนแล้วจะถูกเขียนที่ `artifacts/` (ไม่ได้แนบมาใน zip)

## แอปใช้ผลโมเดลอย่างไร

แอปรันบน Node จึงอ่าน `.pkl` ไม่ได้ สคริปต์ `05` คำนวณผลล่วงหน้าแล้วเก็บเป็น
`src/data/modelOutputs.json` ซึ่งอ่านผ่าน `src/data/modelOutputs.ts` ทุกครั้งที่เทรนใหม่ต้องรัน `05` ซ้ำ

| ส่วนในแอป | มาจาก |
|---|---|
| กราฟพยากรณ์รายวัน (Executive) | โมเดล 04 |
| แผนอบแนะนำ + ความเสี่ยงของเสีย (Kitchen) | โมเดล 04 + 01 |
| กฎ Market Basket และคำแนะนำ Upsell (Manager) | โมเดล 02 |

## ข้อจำกัดที่ควรรู้

- **โมเดล 04** เรียนรู้เฉพาะช่วงชั่วโมงที่ "มียอดขายอย่างน้อย 1 ชิ้น" ถ้าเอาไปทายตรงๆ จะสูงกว่าจริง
  สคริปต์ `05` จึงคูณด้วยความน่าจะเป็นที่สินค้านั้นจะขายได้ในชั่วโมงนั้น (นับจากข้อมูลช่วง train)
- **โมเดล 01** จับของเสียได้ราว 74% แต่เตือนผิดบ่อย (precision ราว 26%) เหมาะใช้จัดลำดับความเสี่ยง
- ตัดโมเดล 03 (Churn) ออกตามที่ตกลง
- ค่าอื่นในแอปที่ไม่ได้มาจากโมเดล (เช่น A/B test, กฎ Dynamic Markdown, กลุ่ม Persona) ยังเป็นค่าตัวอย่างเดิม
